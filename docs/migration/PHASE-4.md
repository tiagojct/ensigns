# Phase 4 delivery

The local product is complete as Ensigns 1.0.0, prepared on 2026-10-04. Checkpoint 3 remains the historical record; the current release keeps the existing primary designs and candidate review alternatives.

## Delivered

- All 29 pure export writers share the resolved token model with the CLI and Carpenter. They preserve authored colours, editor surfaces, complete chart ramps, opacity where supported, syntax styles and non-colour metadata. Missing and excluded palettes have explicit reasons.
- Ten-family static public catalogue, both-mode samples, native specimens for every family, measurement reports, swatches, downloads, independent comparison panels, appearance persistence and a local browser workbench with previews, copy, binary downloads, mode-filtered ZIP bundles and a contrast checker.
- Build-generated family archives and JavaScript, Python, R, Typst, editor, Tailwind, Firefox, Mastodon and Loomings packages. dist/ensigns-1.0.0.zip contains the portable site, package folders, licences and owner instructions.
- Selected font files served locally with original OFL texts and source hashes, CC BY 4.0 legal code, canonical routes, old-name redirects, a sitemap, favicon and social preview.
- Node 24 deployment recipe, static nginx serving under a same-origin CSP, and CI checks and build artifacts without registry publication.
- Rosebud 0.5.0 corrects the dark status accents using existing lighter grey steps. Its four status levels meet the declared text minimum across chrome surfaces and status fills; the native specimen needs none of its three former forced-colours waivers.

## Verification

The repository suite covers schema and semantic validation, migration changes, every declared environment, independent Lua and Adobe binary parsing, Zed's official schema, deterministic exports and hashes, editor manifests and browser mode behaviour. Production-site tests exercise mobile and desktop layouts, local links, every format and real text, binary and ZIP downloads under the deployment CSP. R, Python/matplotlib and Typst package checks are recorded in the release checkpoint.

## Owner operations

No registry or live server is changed by the build. docs/RELEASE.md gives the concrete local artifacts, installation, deployment and publication steps. Historical account verification, registry retirement notices, a Zenodo DOI and updates in other consumer repositories require the owner's accounts. The local implementation does not depend on them.

D22 is satisfied by the bundled official CC BY 4.0 text. D30 is satisfied by Rosebud 0.5.0. The applied choices for the other design decisions are retained and explained in the release instructions. Candidate files remain separate from public primary downloads.
